# 计划书写作方法

这套方法适用于建设、运营、活动、公益及创业等计划书，目标是把初始构想逐步变成有依据、能执行、便于修改的文稿。它规定需要解决的问题与决策方式，不规定所有项目必须使用同一份目录、同一轮数的访谈或同一种审批流程。

阅读导航：第一、二节说明入口和大纲；第三节给出各阶段首问、追问分支与正文起草条件；第四至六节处理事实、论证、方案与经费；第七至九节处理修订、交付和跨对话方法积累。

## 一、先判断从哪一步开始

不要求每次从零开始。只有构想时，先梳理用途与需求；已有目录时，接着写指定章节；已有计划书时，先确认底稿；只有批注时，做局部修改；只要求转 Word 时，直接转换并核查。

| 阶段 | 需要回答的问题 | 主要产物 | 进入下一步的依据 |
| --- | --- | --- | --- |
| 明确任务 | 为谁写、用来做什么、这次做到哪里？ | 写作范围、当前底稿 | 已能判断内容取舍 |
| 构建框架 | 要让读者理解并相信哪些事情？ | 可调整的目录 | 覆盖必要问题，无无关章节 |
| 收集信息 | 已知什么，哪些缺口会改变方案？ | 事实清单、必要问题 | 关键事实够用，缺口已标明 |
| 调查论证 | 需求是否存在，现有资源能否满足？ | 证据、核实表、可行性判断 | 结论有依据，限制可见 |
| 形成方案 | 做什么、由谁做、何时做、如何运行？ | 方案、运营与进度安排 | 措施有负责人、条件与衔接 |
| 核对经费 | 要花多少、何时支出、由谁承担？ | 预算表、资金安排 | 数量与周期一致，缺口可识别 |
| 成稿修订 | 如何准确表达，又不破坏已确认内容？ | 正文、修订稿 | 满足当前要求且关联内容一致 |
| 制作交付 | 文件是否完整、可读、能继续使用？ | 所需格式、附件或资料包 | 内容与版式均完成核查 |

这些阶段可以交叉和回退。例如，预算超过资金能力时，应返回调整规模；新图纸改变数量时，应回到预算和运营安排核对，不能只改一处数字。

## 二、先明确用途，再建立工作大纲

至少识别项目要解决的问题、服务对象、建设或运营主体、计划书用途，以及已知的场地、时间、资金限制。对用户尚未确定的事项保留余地，不让临时猜测进入正式事实。

目录应顺着论证关系展开：为什么需要做 → 准备做成什么 → 怎样建设和运行 → 需要哪些资源 → 如何处理风险并判断成效。根据用途增删章节；筹资材料需要资金与回报或公益成效，内部执行计划需要职责与进度，自主项目不必添加呈递、批复、学院评价等栏目。

用户要求先看目录时先给目录；用户已明确要求完成全文且信息够用时，直接成稿，不把目录确认变成固定审批关卡。

## 三、按阶段选择首问、追问和起草时机

### 每轮如何推进

先用现有上下文填写事实清单，找到当前写作范围内最影响决策的缺口。只有缺口才需要提问；下面的首问是可选入口，不是必须逐条执行的问卷。用户一次回答多个阶段的信息时，一并吸收，跳过已有答案。不适用的阶段或分支直接跳过，不为凑齐信息添加项目没有的场地、收费或持续运营机制。

每轮通常围绕一个决策问 1—3 个短问题，每题承担一个主要判断。不要把十几个子问塞进三道题，也不为凑数量继续问。多个缺口同时存在时，先处理会改变用途、对象、规模、费用、责任或启动条件的事项；预算上限、截止时间等硬约束一旦出现，立即约束方案，不等到后面再处理。

收到回答后，先更新事实、来源和状态，再决定追问、核实还是起草。可以用“已确认……；尚缺……会影响……；本轮先问……”简要衔接；信息已经足够时直接写，不再问“是否可以开始”。

### 阶段一：用途与任务边界

**要作出的判断：** 为谁写、支持什么决定，以及本轮要完成什么。

**缺少用途时先问：** “这份计划书主要给谁看，希望它帮助作出什么决定？”

| 回答情况 | 选择的追问或动作 |
| --- | --- |
| 自主实施或内部讨论 | 只在不明确时追问本轮要目录、章节还是全文；不补学院评价和批复流程 |
| 申报、筹资或对外合作 | 先找已有通知、模板或对方要求；确有缺口时问必须回应的条件，不先收集无关格式细节 |
| 用途尚未定 | 若不同用途会改变核心论证，帮助比较用途差异并请用户选择；可先列共用框架，不替用户确定呈递对象 |
| 已有多份底稿 | 对比范围和版本，能判断的直接整合；仅在主稿选择影响实质时问哪份为基准 |

**足以推进：** 能判断读者、目的和本轮范围，明确必须遵守的限制。以上可以从上下文清楚判断，不必逐项再确认。此时可搭大纲；能否写正文还按下文的章节条件判断。

### 阶段二：服务对象、具体痛点与现有资源

**要作出的判断：** 谁存在什么需求，项目为何需要存在。

**先问：** “最优先服务哪类人，他们目前最需要解决的一个具体问题是什么？”

| 回答情况 | 选择的追问或动作 |
| --- | --- |
| 只有“提升效率、服务同学”等愿望 | 追一个最近的具体经历，例如“最近一次遇到这个困难是什么情境？”；再根据需要核对频率或影响，不一次问完全部细节 |
| 指出了具体问题，但没有证据 | 问判断来自个人经历、访谈、观察还是已有统计；把观察保留为线索，不写成调查结论 |
| 声称现有资源不足或完全没有某项功能 | 先核对比较对象及其使用限制；追问哪些人在哪些情境下仍无法满足需求，必要时查证公开资料 |
| 给出调查结果或比例 | 核对调查时间、对象、样本口径和原始来源；一般兴趣不直接推导为持续使用或付费意愿 |
| 还没调查，或用户不知道 | 形成少量优先核实的问题及采集方法，记录待核实，停止空转追问 |

**足以起草：** 具体对象、问题情境和项目拟补充的价值已清楚，可写初步背景。缺少调查时，只写可追溯的观察、问题线索及核实安排；涉及覆盖人数、普遍程度或“需求已被证实”的结论，必须等待相应证据。

### 阶段三：目标、服务边界与规模

**要作出的判断：** 当前计划要做到什么，以及暂时不纳入什么；有分期时再区分各期范围。

**先问：** “这次计划必须实现的核心结果是什么，哪些内容可以以后再做？”

| 回答情况 | 选择的追问或动作 |
| --- | --- |
| 目标宽泛，无法判断是否完成 | 追问“出现什么具体变化，你会认为这次计划做成了？”；指标可以是交付结果或使用表现，不强制编造数值目标 |
| 一次提出很多服务 | 请用户区分必须有与可延后，比较各项对资源和维护的影响，先形成可承受的范围 |
| 给出一个规模数字 | 核对是同时容量、累计人次、独立人数、采购数还是设计数，以及对应周期 |
| 规模只是愿望，尚无资源依据 | 标为目标或备选方案，回到场地、人员与经费约束验证，不写成已经具备的能力 |
| 目标与硬约束冲突 | 展示需要调整的范围、时间或资金，问真正需要用户选择的取舍；不同时承诺互不相容的条件 |

**足以起草：** 核心结果、优先服务范围与规模口径清楚；未核实规模明确作为目标或备选。此时可写目标和建设内容草稿，不需要所有设备品牌、正式项目名称或采购价格都已确定。

### 阶段四：方案与资源配置

**要作出的判断：** 目标通过什么方式实现，需要哪些资源与前提。

**先问：** “实现核心目标所需的关键资源，哪些已经具备，哪些需要新增？”

| 回答情况 | 选择的追问或动作 |
| --- | --- |
| 提供场地、图纸或设备清单 | 仅对涉及这些资源的项目，区分已落实、设计、实测及可用状态；优先核实会改变容量和费用的尺寸或条件 |
| 只有功能愿望，没有实施方式 | 给出少量可比较的方案及其成本、维护差异；请用户决定影响方向的选择，普通配置可作为明确标注的建议 |
| 已有资源但可用性不清 | 问是否可按计划时段使用、由谁提供，以及还缺什么条件；“有人愿意支持”不等于资源已落实 |
| 细节尚未确定，但主要方式明确 | 用功能要求或配置范围起草，细节列待核实；不因未定品牌阻塞正文 |

**足以起草：** 主要服务方式、关键资源、初步数量口径和依赖关系能对应上目标。可写方案草稿；未经核实的精确尺寸、最终容量和资源可用性不能作确定性陈述。

### 阶段五：运营机制与责任

**要作出的判断：** 项目如何持续交付，谁承担关键工作。

**先问：** “项目开始运行后，谁负责日常交付和维护？”

| 回答情况 | 选择的追问或动作 |
| --- | --- |
| 只有“大家一起管理” | 追问谁作日常决定、出现缺岗时由谁接替，优先解决关键职责空缺 |
| 有团队或明确负责人 | 按项目实际需要补服务流程中的缺口，例如准入、预约、交接或退出；不强制所有项目采用同一套规则 |
| 尚无人承接某项工作 | 将职责写为拟设岗位或未落实条件，核对人力负担；不虚构具体人员已同意承担 |
| 强调公益性或收费服务 | 追问会影响权益和资金使用的规则；区分理念、拟议机制和已确定政策，不将公益直接等同于永久免费 |

**足以起草：** 服务对象、基本交付流程和关键责任角色可说明。职责可以写为拟议安排，不必等真实姓名全部确定；无人承担的关键任务应保留为启动前待落实事项。

### 阶段六：预算、资金与可行性

**要作出的判断：** 成本口径是什么，资源是否足以支持方案。

**先问：** “这次预算需要覆盖哪些项目和时间周期？”已有明确范围时直接使用。需要判断资金可行性时，再核对资金上限、来源及是否已落实。

| 回答情况 | 选择的追问或动作 |
| --- | --- |
| 只给一个金额 | 先问它是单价、成套总价、月费还是资金上限，并核对数量或周期 |
| 总价已知，但新配置数量变化 | 保留总价的暂定性质，核实报价覆盖范围；不按数量比例擅自重算 |
| 有些项目没价格 | 标待询价／未计入，先给已知小计；需要估算时注明依据和范围，不把缺价填零 |
| 资金只是预期赞助、补贴或收入 | 分开已落实与拟筹集，核对到账条件和时间；仅在影响可行性时讨论不足时的方案 |
| 成本超过资金或人力能力 | 优先回到规模与配置取舍，可比较减项、分期或增加可靠资金来源；不预设涨价一定可行 |
| 用户只要求成本表 | 完成费用核对和表格，不以尚未确定收费、赞助或盈利模式为由阻塞出表 |

**足以起草：** 费用范围、单位、周期以及已知和未知项目能够区分，即可写预算草稿或已知成本表。要判断收支平衡或资金充足，还需相应数量、完整费用口径、收入假设与资金状态，不能用不完整小计支撑肯定结论。

### 阶段七：进度、风险与成效

**要作出的判断：** 何时达到什么状态，前提是什么，怎样判断效果。

**先问：** “期望什么时候达到什么状态，这个时间是否为硬性要求？”

| 回答情况 | 选择的追问或动作 |
| --- | --- |
| 截止日期固定 | 优先核对前置任务和所需时间；出现冲突时明确要调整的范围或条件，不编造可完成的工期 |
| 时间尚未定 | 使用相对阶段和启动条件，例如资金、资源到位后推进；不必为写作强迫用户编出日历日期 |
| 有明显不确定条件 | 追问若条件未满足会怎样处理、由谁决定；为关键风险安排触发条件和应对动作 |
| 成效只有“满意、有效”等词 | 问用什么可观察结果判断，选择适合项目的使用、交付或改善指标；没有基线时安排采集，不捏造提升比例 |

**足以起草：** 主要里程碑、关键依赖、责任角色及判断结果的方法可说明。可以保留相对时间和待落实条件；对外承诺日期、保障能力和量化效果，需要相应依据。

### 阶段八：正文、修订与交付范围

**要作出的判断：** 现在应交付什么，哪些内容需要保留。

**仅在范围不清时先问：** “这一轮先看哪个部分，还是需要一份完整讨论稿？”用户已要求某章、全文或指定修改时直接照做。

| 回答情况 | 选择的追问或动作 |
| --- | --- |
| 要某一章节 | 只按该章的最低信息条件检查，不因其他章节缺预算等信息而等待 |
| 要全文但核心方向未定 | 优先问影响主线的决定；若用户明确要求先出稿，可用占位或方案分支形成讨论稿，不暗中替用户作决定 |
| 要正式交付 | 对照实际用途查缺；只问影响证据、结论或必须填写内容的事项，不重新访谈已明确部分 |
| 局部修改或批注 | 定位改动与直接联动，范围清楚则直接改；只有存在实质歧义时追问 |
| 只转格式或重新打包 | 使用当前指定稿核对内容和版式，不重启前七阶段；格式确有必要选择且无默认时才问 |

**足以交付：** 达到所需稿件层级，内容和附件与当前决定一致，并完成对应格式核查。成稿与项目具备实施条件是两件事。

### 通用追问规则：根据回答改变问题

| 回答类型 | 下一步 | 结束追问的条件 |
| --- | --- | --- |
| 具体且来源清楚 | 记录值、范围与状态，进入下一缺口或起草 | 当前判断已有依据，不继续扩展无关细节 |
| 模糊或抽象 | 追一个实例、边界或可观察结果 | 能转化为具体对象、情境或措施 |
| 只有数字 | 核对单位、周期、覆盖对象和来源中的实际缺项 | 该数字能被正确用于文字或计算 |
| 不知道 | 可逆方案可给带依据的建议；事实缺口给核实方法、责任或待办 | 已明确如何处理未知；没有新线索时不换句话反复问 |
| 相互冲突 | 先分清时间、范围、设计与实际等口径，仍冲突才请用户选择有效值 | 当前使用哪个值及其影响明确 |
| 一次补充很多信息 | 同时更新相关阶段，只追仍有影响的缺口 | 不按固定问卷重问已回答内容 |
| 暂时不想回答或要求先写 | 按当前事实写可独立部分或明确标注的讨论稿，保留依赖项 | 不把沉默当认可，不借假设宣称事实已经成立 |

每次追问应能说明它会改变哪段正文、哪项计算或哪项决策。若不同答案不会影响当前成果，通常不值得现在问。

### 正文起草条件：按章节判断，不按信息百分比

| 可先写的部分 | 最低信息条件 | 可保留的缺口 | 需要暂缓的确定性表述 |
| --- | --- | --- | --- |
| 项目概况 | 用途可判断，核心对象、问题、拟提供的服务及主体或拟议角色可说明 | 工作名称、非关键细节、后续预算 | 未核实规模、已落实资源或已获批准等断言 |
| 背景与需求 | 对象、具体问题、既有资源及拟补充价值可说明，线索来源可追溯 | 调查结果与部分外部资料 | 无证据的普遍性、比例、需求已经证实等结论 |
| 建设或实施方案 | 核心功能、初步规模口径、关键资源与依赖清楚 | 品牌、精细尺寸、非关键配置 | 未核准容量、未落实使用条件或已完成采购 |
| 运营机制 | 基本服务流程与关键责任角色可说明 | 负责人姓名、可调整的细则 | 未经确认的人员承诺或不可支持的保障能力 |
| 预算与资金 | 清单范围、单位、周期、已知价格与未知项目可区分 | 待询价行、待落实资金 | 用部分成本宣称资金充足、确定收费或可盈利 |
| 进度、风险与成效 | 主要阶段、前置条件和判断结果的方法可说明 | 日历日期、待采集基线 | 无依据的工期保证、效果比例或已具备执行条件 |

需要区分三种稿件状态：

- **章节草稿：** 本章核心关系清楚，缺口不迫使助手替用户作关键决定，即可写。只暂缓受缺口影响的断言，不等待其他章节全部完备。
- **完整讨论稿：** 能用连贯主线或清楚区分的备选方案组织各必要章节，有事实、明确标为建议的措施或可见的待定分支，费用口径和关键依赖能说明。估算、占位和备选方案保留状态，不能包装成用户已确认决定。
- **正式用途成稿：** 符合实际用途要求，影响核心结论的冲突已处理，事实与承诺有依据，尚未落实条件明确呈现。筹资稿可以写资金申请与用途；不能因此写资金已到位。正式成稿不等于已获批、已建设或可立即执行。

“关键缺口”取决于当前写作任务：若不同答案会改变对象、主线、规模、费用、责任或启动条件，就先解决或显式保留分支；若仅影响其他章节或普通编辑细节，不阻塞当前正文。用户明确要求先看草稿时，可以交付带占位和条件的版本，无需凑出“信息已完整”的假象。

### 简短示例：已有信息足以先写一章

用户：“学社想为学生做一个固定工位空间，供内部讨论，先写项目概况。”

如果对象和痛点仍不清楚，先问：“最优先服务哪类学生，最需要解决的一个问题是什么？”

用户：“主要面向本科生，他们缺少长期稳定工位。房间已选定，预算还没核算。”

此时可以写项目概况草稿，写清服务对象、拟提供的服务和发起主体；将工位不足作为发起方提出的需求线索，房间按用户提供的信息记录，不添加未给出的容量、调查结论和审批状态。预算未核算不阻碍本章。只有后来需要写背景、场地或预算时，再分别核实需求证据、场地条件和费用，不顺带启动一整套额外访谈。

## 四、把事实、估算和建议分开

维护一份轻量事实清单，随修改更新，而不是凭最新一段聊天覆盖所有历史信息。

| 事项 | 当前值及单位／范围 | 状态 | 来源与时间／版本 | 影响位置 |
| --- | --- | --- | --- | --- |
| 待填 | 待填 | 用户明确／外部核实／估算／推导／待核实／已删除 | 待填 | 章节、预算、附件等 |

同一事项可能有多个有效口径：设计席位不等于实际可用席位，可用席位不等于付费人数；预算不等于报价，报价不等于成交支出。差异先看时间、范围与状态，再判断是否冲突。

用户最新明确修改对其指定事项生效。外部资料包作为底稿时，保留与当前要求不冲突的内容，逐项应用修改；既不让旧附件把新要求覆盖回去，也不因为新包到来就抹去用户此前的明确决定。

## 五、让建设背景成为有依据的论证

建设背景应说明具体问题、现有资源、未满足需求，以及本项目能够提供的补充。比较时选择同一对象和相近情境，例如服务时段、使用稳定性、准入方式、设施和费用。描述差异前先核实，避免将现有服务一概写成没有某项功能。

证据可以来自现场观察、访谈、问卷、公开资料或实际运行记录。每项结论应能回到来源、日期、对象和口径。用户提出的痛点是调查线索，不能直接改写成“调查显示”。公共事实涉及变化时，使用前核实。

尚未调查时，先制作核实表：

| 待核实问题 | 对象／样本口径 | 方法 | 结果 | 证据与日期 | 状态／限制 |
| --- | --- | --- | --- | --- | --- |
| 待填 | 待填 | 访谈、观察、问卷、查阅等 | 留空待填 | 待填 | 待核实 |

将一般兴趣、持续使用意愿和付费意愿分别核实；未填写不代表零，少量样本不代表总体。发现需求不足或条件不具备时，调整规模、分期建设或先试运行，而不是继续扩写肯定结论。

## 六、把方案、经费和执行条件放在一起检查

方案至少交代服务内容、资源配置、责任主体、日常运行、实施节点，以及出现问题时的处理办法。每项主要措施应能说明谁来做、依赖什么、何时可以完成、以什么结果判断完成。风险措施应有相应资源与可执行动作，不能只写“加强管理”。

图纸支持初步数量与功能分区判断。统计时区分单元和组合：一组双人位、一个单人位、会议席位等分别计数；无法从图中确认的尺寸或条件列为现场核实项。示意图不等于实测或已核准的容量。

预算核对采用以下顺序：

1. 明确数量、单位、配置范围与报价覆盖范围，成套价避免重复计费。
2. 分开一次性投入、月度费用和其他周期费用。
3. 已有价格计入已知小计，未定价项目标待询价，已删除项目彻底移出。
4. 分别计算首月费用、持续月费及启动现金需求，押金和预付项目按其性质列示。
5. 对照已落实资金检查缺口；未落实补贴、赞助或收入保留为条件。
6. 必要时测算不同使用人数下的成本覆盖水平，说明假设，不把测算结果当作已确定收费。

数量改变不代表整批总价可以按比例改写。若用户给定的总价覆盖范围不清，应暂留并标注待核价，不能用看似精确的推算代替报价。预算调整后同步正文、配置表、合计与附件。

公益性按项目实际定位表达，可体现为面向谁服务、费用如何确定、资金如何使用、困难群体如何获得支持及如何公开管理；不替项目承诺尚未落实的免费服务或补贴。其他项目应按其自身目标写作。

## 七、成稿后用变更范围控制修订

逐章共创适合信息不断补齐、需要讨论定位的项目；信息充分时也可以直接完成全文。无论采用哪种方式，都要区分已确认事实、拟议措施和待核实条件。

每次修改先识别四件事：

| 事项 | 判断方法 |
| --- | --- |
| 用户明确要改什么 | 定位句子、字段、章节、费用行或文件 |
| 哪些必须联动 | 检查合计、目录、交叉引用、配置、图注和附件 |
| 哪些应保持 | 不受本次改动影响的文字、表格及格式 |
| 怎样确认改对 | 核对目标内容、关联内容及旧值是否残留 |

局部批注优先局部修改；全局术语调整按语境判断，保留对照对象、机构名称和引用资料的准确名称。删除某项呈递或评价流程，不等于删除实际运营所需的职责、内部复盘或责任承诺。

如果用户指定“仅改对应内容、保留格式”，应使用适合该文件的精准编辑方式。只有修改造成必要分页变化时才处理相关排版，不借机重写全篇。

## 八、把内容核对与文件核对都做完

Markdown 适合持续编辑与保存正文；Word 适合正式阅读、打印与交换；表格适合预算与调查记录。根据用户需求选择格式，不为显得完整而额外生成无关文件。

交付前至少检查：

- 用途、标题、主体、服务对象和规模是否与当前决定一致。
- 数量、金额、单位、时间周期及相关附件是否一致。
- 待核实事项是否仍明确，是否出现未经确认的调查结果或承诺。
- 已删除项目、旧称谓和失效段落是否在目录、附件等位置回流。
- 文件是否实际保存；Word 是否渲染检查；表格公式、图片、分页与签署区是否可用。
- 资料包是否使用同一轮正文、预算和图纸，附件与链接是否完整。

最后说明交付了什么、完成了哪些核查、还存在哪些会影响使用的缺口。没有实际执行的调查、测试、保存、归档或同步不写成已完成。

## 九、跨对话积累方法时保留来源边界

把可复用的方法写成“出现什么情况 → 为什么这样判断 → 采取什么动作 → 如何核查”。例如，新图改变数量时，应复核采购和预算口径；用户只要求转格式时，应保留内容并做排版检查。

分别标记直接可见的协作记录、用户转述的流程摘要，以及上传材料反映的内容。只说明实际读取过的其他聊天，不把未知来源的文件推断为某个聊天的产物。

后续合并流程片段时，去除重复动作，保留分支条件与例外；项目的具体地址、价格、章节数、公益定位和呈递要求不自动成为其他项目的默认值。方法是否有效，应看它能否减少重复提问、暴露关键缺口、控制修改范围并维持正文与附件一致。
